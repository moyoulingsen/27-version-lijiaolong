# 在 Jazzy 宿主机上启动 Humble 容器并构建 mid360_ws

宿主机是 ROS 2 Jazzy 时，不要在宿主机直接构建这个工作空间。下面的命令会
启动一个 ROS 2 Humble 容器，把宿主机的新工作空间挂载为容器内的 `/ws`，然后
在容器内执行 `colcon build`。

## 推荐：一条命令直接启动图形化 Gazebo

仓库中已提供专用脚本，它会自动：

- 停止旧容器中残留的 Gazebo；
- 删除同名的旧停止容器；
- 挂载 `mid360_ws`；
- 转发 DISPLAY 和 Xauthority；
- 临时允许容器内 root 访问宿主机 X11；
- 在 Humble 容器内重新构建；
- 直接启动 Gazebo GUI；
- Gazebo 退出后保留一个 Humble shell。

在宿主机执行：

```bash
cd "/home/lijiaolong/桌面/27-version-lijiaolong"
./docker/run-mid360-gui.sh
```

脚本文件：

```text
docker/run-mid360-gui.sh
```

这条命令执行期间不要再在 `ros-humble-task` 或另一个终端启动 Gazebo。

## 第一次使用：从现有项目容器创建专用镜像

原项目容器名是 `ros-humble-task`。如果它已经存在，先启动它并将其保存为一个
带有项目依赖的本地镜像：

```bash
docker start ros-humble-task
docker commit ros-humble-task ros-humble-task-mid360:local
```

`docker commit` 只需要执行一次。它不会把旧工作空间的挂载内容复制进镜像，
新容器会单独挂载下面的 `mid360_ws`。

## 第一次创建并进入新容器

在宿主机终端执行：

```bash
docker rm -f ros-humble-mid360 2>/dev/null || true

docker run --name ros-humble-mid360 \
  --gpus all \
  --network host \
  -e DISPLAY="${DISPLAY:-:0}" \
  -e QT_X11_NO_MITSHM=1 \
  -v /tmp/.X11-unix:/tmp/.X11-unix:rw \
  -v "/home/lijiaolong/桌面/27-version-lijiaolong/路径规划与SLAM/mid360_ws:/ws" \
  -it ros-humble-task-mid360:local bash
```

如果你只想无图形界面运行，也可以去掉 `DISPLAY` 和 `/tmp/.X11-unix` 两项；
不过相机图像需要 Gazebo 渲染环境，建议保留它们。

## 以后再次使用

容器创建过之后，宿主机执行：

```bash
docker start -ai ros-humble-mid360
```

## 容器内构建新工作空间

进入容器后执行：

```bash
cd /ws

source /opt/ros/humble/setup.bash

rm -rf build install log

colcon build --symlink-install

source install/setup.bash
```

这里构建的是：

```text
/ws/src/bot_description
/ws/src/ros2_livox_simulation
```

## 容器内启动机器人

继续在容器内执行：

```bash
ros2 launch bot_description gazebo.launch.py
```

## 如果提示 `Address already in use`

Gazebo Classic 默认使用 `11345` 端口。同一台宿主机上使用
`--network host` 的多个容器只能同时运行一个 Gazebo master。若上一次启动
被强制中断，先在宿主机执行：

```bash
docker exec ros-humble-task pkill -x gzserver 2>/dev/null || true
docker exec ros-humble-task pkill -x gzclient 2>/dev/null || true
docker exec ros-humble-mid360 pkill -x gzserver 2>/dev/null || true
docker exec ros-humble-mid360 pkill -x gzclient 2>/dev/null || true
```

确认端口已经释放：

```bash
ss -ltnp | grep 11345 || true
```

没有输出后，再进入新容器启动：

```bash
docker exec -it ros-humble-mid360 bash
cd /ws
source /opt/ros/humble/setup.bash
source /ws/install/setup.bash
ros2 launch bot_description gazebo.launch.py gui:=false
```

正常退出时回到启动终端按一次 `Ctrl-C`，不要同时在旧的
`ros-humble-task` 容器里运行 Gazebo。

或者无图形界面运行：

```bash
ros2 launch bot_description gazebo.launch.py gui:=false
```

## 容器内验证 MID360

另开一个宿主机终端，进入同一个已经运行的容器：

```bash
docker exec -it ros-humble-mid360 bash
```

然后：

```bash
source /opt/ros/humble/setup.bash
source /ws/install/setup.bash

ros2 topic list
ros2 topic echo /mid360_points --once
ros2 topic echo /camera/camera_info --once
```

应该能看到：

```text
/mid360_points
/camera/image_raw
/camera/camera_info
/tf
/tf_static
/odom
```

## 如果 `ros-humble-task` 不存在

可以直接使用 Humble 基础镜像创建容器，但需要先安装 Gazebo 和构建依赖：

```bash
docker run --name ros-humble-mid360 \
  --gpus all \
  --network host \
  -e DISPLAY="${DISPLAY:-:0}" \
  -e QT_X11_NO_MITSHM=1 \
  -v /tmp/.X11-unix:/tmp/.X11-unix:rw \
  -v "/home/lijiaolong/桌面/27-version-lijiaolong/路径规划与SLAM/mid360_ws:/ws" \
  -it osrf/ros:humble-desktop bash
```

进入后安装依赖：

```bash
apt-get update
apt-get install -y \
  ros-humble-gazebo-ros-pkgs \
  ros-humble-gazebo-plugins \
  ros-humble-xacro \
  python3-colcon-common-extensions
```

然后回到上面的 `/ws` 构建步骤。
