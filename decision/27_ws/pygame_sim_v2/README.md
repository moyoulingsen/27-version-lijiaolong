# RMUC 2026 Pygame 二维验证器 v2

## 运行

推荐直接用 v2 专用启动脚本：

```bash
cd "/home/lijiaolong/桌面/27-version-lijiaolong/decision/27_ws/pygame_sim_v2"
./run_pygame_sim_v2.sh
```

真实数据集回放使用原有 `SimulatorApp` 的回放分支；它不会把历史状态写回决策验证器或 SQLite：

```bash
./run_replay.sh
# 或指定某一局
./run_replay.sh --game-id 1778631047459
# 也可以从统一入口启动
./run_pygame_sim_v2.sh --replay --game-id 1778631047459
```

回放器以只读方式打开 `decision/data/rmuc_2026_region_dataset.sqlite`，从
`matches` 读取局索引、从 `timeseries` 读取机器人逐秒状态、从 `events` 读取
射击/受击/装配/能量机关/飞镖/雷达/增益事件。逐秒状态之间按位置、血量、热量、
功率、发弹和金币插值，枪口朝向使用最短角度插值；空中单位只在数据集实际有行的
出动区间显示。建筑行的 `(0, 0)` 是数据集占位值，回放器按场地固定位置绘制基地
和前哨站。
少量原始轨迹坐标会越出 `[0, 28] × [0, 15]`（传感器噪声或越界记录）；回放数据层
保留原值，地图仅将标记夹到最近边界并用橙色圈提示，不静默改写数据。

回放时 `timeseries` 是属性、位置、血量、热量、功率、金币和累计发弹的唯一状态源；
`events` 只按回放时间进入事件日志和经济推断，不再次扣血或扣弹，避免事件与状态快照
双重应用。`累计17mm发弹`/`累计42mm发弹`是独立的只读累计遥测属性，不是剩余弹量；
实时仿真里的“当前弹量”仍表示规则剩余弹量；回放明确显示数据集未提供剩余弹量，SQLite 的
`NULL` 累计计数显示为“不适用”，不会拿累计发弹替代弹量。
金币推断遵循规则书的定时收入、装配/科技核心收入、17/42mm 本地/远程兑换、空中支援、
远程回血、立即复活、雷达反制后空中支援兑换、自动哨兵指令费和哨兵补给区额度；由于数据集
没有交易流水，面板同时显示候选行为和置信度。规则书规定四级装配失败后每 10 秒收入减少 25，
但当前 `events` 不记录装配失败，无法确认是否发生该行为，因此不从金币余额臆测该惩罚。

回放控制：空格播放/暂停，`←/→` 单步一秒（配合 Shift 为十秒），`+/-` 调整
0.25x～8x，`L` 循环，`N/B` 切换下一局/上一局，`Home/End` 跳到首尾；底部时间
轴支持鼠标拖动。可用 `--region`、`--school` 筛选局列表。

这是一个与 ROS 2/Gazebo 解耦的轻量二维验证程序，用于先行确认哨兵坐标、任务场景输入、人工移动、小陀螺、云台和高层决策输出。

> 本目录是 `decision/27_ws/pygame_sim` 的独立副本；v1 目录保持原样。
> v2 相对 v1 的规则增强见 [`V2_CHANGES.md`](V2_CHANGES.md)。

## v2 规则增强

- 420 秒到点自动结束，并按基地、前哨、全队伤害、总剩余血量判定胜负。
- 建筑命中分档：基地前装甲 17mm 为 5/8，其余装甲 20/30；42mm 200/300。
- 自瞄、云台跟踪和开火不再使用墙体 LOS 阻挡；行为树历史目标 `(17.0, 10.0)` 由桥接层转换为新的场地图红点攻击位置 `(13.440, 11.140)`。
- 云台未进入 4° 开火容差前不会停止转动；自动射击只有真正形成射门才扣弹/加热。
- 弹量条按上限 1000 显示，并在 300 处标出初始允许发弹量。
- 补给区回血按 10%/秒，比赛 4 分钟后脱战为 25%/秒；补弹不再要求空弹。
- 经济初始 400，并按规则表 5-5 定期发放。
- `confirm_respawn` 真正门控 5 秒复活；复活保留弹药，热量/缓冲能量重置。
- 姿态的防御/易伤/冷却/功率倍率生效；热量 Q1/Q2 锁定和 60 J 缓冲/5 秒断电生效。
- 机器人接触阻挡时按撞击 2 点结算，带 0.5 秒冷却。
- 经济兑换、远程回血、立即复活、规则书读条复活和无敌/虚弱状态已接入右侧“规则操作”。
- 等级/经验表 5-12～5-16、英雄/步兵性能切换、姿态强化 15 秒和 3 分钟衰减已接入。
- 碰撞和导航使用官方 PGM 原始障碍，并叠加按类型区分的机器人碰撞体；基地和前哨站不再额外添加静态碰撞体，可在右侧切换显示。
- 场地增益点、中央/梯形高地、公路/高地/飞坡/隧道、能量机关已接入二维区域和属性 buff；中央高地按每块区域独立、双方互斥占领，地形跨越按每台地面机器人的卡序列、时间窗、叠加、冷却和死亡清除独立结算。
- 工程装配、飞镖闸门/伤害、雷达标记/易伤已接入顶部“子系统面板”（F9）。科技核心使用地图编辑器中的“装配区增益点（红方）”作为触发范围：一级开启周期金币，二级解锁己方 7 级上限，三级解锁 10 级和己方地面机器人/前哨/基地 25% 防御，四级提高为 50% 防御并将基地增加的 2000 血量溢出部分转为虚拟护盾。

## 控制

| 输入 | 行为 |
| --- | --- |
| `1/2/3/4/8`（主键盘或小键盘） | 选择对应编号的蓝方地面机器人 |
| `9`（主键盘或小键盘） | 选择己方哨兵机器人 |
| `Ctrl+1/2/3/4/5`（主键盘或小键盘） | 选择并驾驶己方英雄、工程、步兵或空中单位 |
| `F1/F2/F3/F4/F5` | 分别选择并驾驶我方 1/2/3/4/5 号机器人 |
| `F8` | 选择并驾驶我方 8 号哨兵机器人 |
| `F6/F7/F9/F10` | 未绑定；6、7 号为建筑，9、10 号不存在对应机器人 |
| 右侧机器人名称 | 悬停显示属性，移开隐藏；点击固定属性面板，再点“取消固定”关闭 |
| 属性面板中的“驾驶” | 驾驶对应机器人；己方 8 号使用原来的哨兵状态 |
| `W/A/S/D` 或方向键 | 沿世界坐标轴移动；对角输入会归一化 |
| `空格` | 暂停或继续比赛；暂停时冻结计时、自动移动、射击耗弹和扣血，但仍可人工调整机器人位置 |
| `鼠标左键` | 选择己方哨兵后按住人工开火；只有枪口实际对准射程内目标才扣血，点击界面按钮不会开火 |
| `P` | 暂停或继续比赛的备用按键 |
| `0` 或左/右 `Shift` | 退出人工控制并切回行为树/本地自动控制 |
| `R` | 重新启动当前验证场景，切回自动控制并复位行为树运行状态 |
| `Ctrl+S` | 保存当前场景，包括全部位置、血量、弹量、时间、角度和巡逻模式 |
| `Esc` | 退出程序 |

被选中的蓝方或己方机器人会显示金色控制环，顶部坐标栏切换到该机器人；每个机器人上方会显示编号和名称。右侧“己方控制与机器人属性”面板上部显示己方前哨、基地血量和基地虚拟护盾，下部使用“己方/敌方”标签切换对应一方的机器人和建筑列表，并同时显示血量数字与血条；每个有地面装甲血量的条目都可用行内 `-`、`+` 按钮手动调节。原 F1–F10 场景注入功能已经移除，功能键现在只用于选择我方机器人。“自动控制 0”和“重新启动 R”保留在左侧面板。悬停名称显示基本属性，移开隐藏；点击名称将面板固定，直到点击另一个名称或“取消固定”。固定后可操作属性面板里的血量、己方弹量和驾驶按钮。

己方其他机器人只属于二维显示、属性面板、手动驾驶和碰撞层，不进入 `TaskScenario.evaluate()`、残血目标选择、开火目标选择、行为树输入或 ROS 桥接消息。蓝方 5 号为空中单位，本二维地面移动验证不提供地面人工驾驶。己方 5 号空中单位可在二维投影中进行位置验证。所有机器人（含空中单位的二维投影）统一采用参考模型底盘约 0.52 米方形外接圆，碰撞半径约 0.39 米；移动时会阻挡地图障碍并与两队其他机器人保持碰撞间距，自动寻路也会绕开机器人。这是二维运动碰撞模型；空中单位按规则不承受地面装甲攻击或撞击扣血。

云台在没有射击锁定时自动扫描，发现行为树选定目标后由模拟自瞄逐步对准。地图使用与云台同轴转动的两个扇形：青色 6.2 米扇形表示可发现并上报行为树的目标，橙色 4.0 米扇形表示允许开火扣血的攻击范围。行为树的 `shoot_mode` 只代表开火请求，地图只验证攻击范围和 4° 枪口夹角，不使用墙体视线阻挡。按 `9` 进入己方哨兵人工控制后，可在枪口扫过目标时按住鼠标左键锁住当前枪口方向并人工射击，松开左键后继续扫描。任意一方基地血量归零或 420 秒比赛时间耗尽时，比赛结束并按规则书 5.8 判定胜负、触发归位。

自瞄只向行为树发送相机视野内目标的相对极径和极角。ROS 桥同时发布机器人自身的 `map -> camera_link` 变换，决策端据此解算目标地图坐标并生成追击点；可见目标不会读取裁判/雷达中的敌方绝对坐标。雷达绝对坐标仅保留给“自瞄无目标”时的独立雷达联动逻辑。

场地还会显示两方基地/前哨、双方各 6 个机器人、补给区域、两套巡逻路线、6.2 米探测扇形、4.0 米攻击扇形、当前行为、血量、弹量、经济以及姿态/复活/云台/小陀螺/射击/目标输出。保守路线与激进路线会同时显示，当前使用的路线以更粗、更亮的线条高亮；只有 HP < 150 且经济 < 400 时选择保守路线并关闭云台，HP >= 150 或经济 >= 400 时选择激进路线并开启云台。低于回血阈值时，主行为树仍按既有优先级先前往补给区回血。经济位于左侧底部，可按 50 为步长在 0–1000 范围内调节。两套路线均按 `1 → 2 → 3 → 1` 闭环巡逻。射速仍可在左侧按 1–20 发/秒调节；单发原始伤害固定由规则弹种及命中部位决定。

界面采用左侧裁判状态、中央地图、右侧单一控制面板的布局。比赛时间旁的 `-`、`+` 每次调整 10 秒；“重置”会将时间、全部单位位置、属性、建筑、人工控制和行为树运行状态恢复为新比赛默认值，但不会删除底部长期场景存档。己方机器人的位置、属性及当前驾驶对象会随场景存档恢复。界面可见文字统一使用中文。

窗口底部是类似 Excel 工作表的场景存档栏。按 `Ctrl+S` 或点击 `+` 会新建“场景 1、场景 2……”标签，存档持久化在项目内的 `scenario_saves.json`；程序下次启动时会自动读取，因此关闭窗口或重启电脑后仍然存在。点击任一标签会恢复当时的全场状态，点击标签右侧的 `×` 会立即删除该存档并同步更新本地文件。载入场景后点击“重新启动”或按 `R`，程序会发送新比赛复位信号并切回自动控制，让行为树从该存档状态重新开始验证。

地图区域编辑是独立的永久配置，保存到项目内的 `map_regions.json`。绘制、编辑、删除或切换自定义区域显示状态后会立即写入，不需要再按 `Ctrl+S`；载入场景也不会覆盖这份区域配置。

场景遵守主行为树优先级。开局会在前往前哨攻击点时开启云台扫描；2 号工程机器人不会加入攻击目标。只要在 6.2 米探测范围内发现低于 50 HP 的敌方机器人，该目标会立即抢占前哨和回血任务：4 米外主动追击，进入 4 米后攻击，即使此时前哨已经可以射击或己方哨兵已经低于回血阈值。残血目标消失或被摧毁后，再恢复前哨任务或回血。1 秒内累计扣血达到 30 且达到阈值时未检测到敌人，会立即切换为防御姿态、高速小陀螺、开启云台并执行不规则局部机动；一次 25 HP 误伤不会触发，两次快速点击累计 50 HP 会触发。连续 5 秒无显著伤害后继续原任务。

任务说明的生产代码覆盖情况见 [`TASK_COVERAGE.md`](TASK_COVERAGE.md)。Pygame 中的场景显示用于验证输入和期望结果，不代表对应能力已经进入 ROS 2 主行为树。

## 规则属性与伤害

属性来源为仓库中的《RoboMaster 2026 机甲大师超级对抗赛比赛规则手册 V2.2.0（20260807）》第 3 章、表 5-2、表 5-7、表 5-13 至表 5-16，以及 5.5.1、5.5.3。未另选性能时，按手册默认使用英雄远程优先、步兵血量优先底盘与冷却优先发射机构。英雄、步兵、空中的热量上限、冷却速率和底盘功率上限会随裁判系统等级动态更新；哨兵采用自动哨兵配置。属性面板会注明配置。

| 单位 | 初始/上限 HP | 开局允许发弹量 | 功率上限 | 热量上限 | 基础冷却/秒 |
| --- | --- | --- | --- | --- | --- |
| 英雄 | 200 | 0 | 50 W | 160 | 20 |
| 工程 | 250 | 不适用 | 120 W | 不适用 | 不适用 |
| 3/4 号步兵 | 200 | 0 | 45 W | 40 | 12 |
| 空中 | 不适用地面装甲 HP | 750 | 不适用 | 100 | 20 |
| 自动哨兵 | 400 | 300 | 100 W | 260 | 30 |

地图上的机器人机构按规则功能做了二维投影：英雄、步兵和自动哨兵显示可独立瞄准的云台与底盘小转盘；空中单位显示云台；工程机器人显示底盘小转盘但不显示武器云台。右侧机器人属性弹窗同时显示云台/小转盘是否配置、当前底盘功率与动态功率上限、当前热量、Q0/Q2、单发热量、10Hz 冷却速度和锁定状态。裁判面板可为双方英雄、步兵、空中和哨兵记录模拟发射；17mm 每发增加 10 热量，42mm 每发增加 100 热量，Q1 锁定至热量为 0，Q2 当局永久锁定。所有新字段随场景存档保存。

现在双方英雄、步兵 3/4、空中机器人和哨兵均接入同一裁判射击链路。在射手属性弹窗点“选择射击”，再点击对方机器人或建筑，裁判系统会统一检查存活、虚弱、复活禁火、弹量、Q1/Q2、射程、对准和墙体视线，然后结算扣弹、增热、命中部位、防御/无敌和伤害。该入口只接收外部给定的射手、瞄准角和目标，不修改行为树输出。

实际哨兵射击走统一规则伤害接口，不再使用可手调的单发伤害。普通 17mm 命中地面机器人/前哨为 20，42mm 为 200；基地上方前装甲的 17mm 原始伤害为 5，其余基地装甲为 20。基地/前哨中心 10mm×10mm 区域命中获得 150% 攻击增益，同类攻击增益取最大值。v2 不再把所有建筑命中都当成中心暴击：用弹道相对建筑中心的横向偏移 ≤ 5mm 判中心命中；基地前装甲 17mm 为 5/暴击 8，其余装甲为 20/暴击 30，42mm 为 200/暴击 300。最终弹丸伤害为 `原始伤害 × 攻击增益 × (1 − 有效防御增益)`，逐发四舍五入后累计；负防御表示易伤。基地/前哨初始 HP 分别为 5000/1500，基地开局 150 虚拟护盾优先扣除；己方前哨存活时己方基地无敌。双方建筑均遵守这一保护条件。

伤害接口可以通过 `critical_zone` 和 `armor_zone="upper_front"` 明确指定暴击或基地上方前装甲命中，并通过 `attack_buff`、`defence_buff` 传入有效增益。`apply_attack_damage(..., team="red")` 也可用于己方场景单位受到外部伤害；这不会把己方其他机器人接入决策。

地面机器人装甲被判定为撞击时，原始伤害为 2，并适用防御增益；基地、前哨和空中单位不使用该 2 点扣血。v2 在机器人接触并被阻挡时按撞击 2 点结算，带 0.5 秒冷却；墙、基地、前哨和空中单位不触发。热量现在会在超过 Q1 时锁定发射机构、超过 Q2 时当局永久锁定；底盘功率按 60 J 缓冲能量结算，耗尽后断电 5 秒。哨兵瞬时底盘功率已取消 `65/18/8` 固定系数，改用 `scut_gazebo_simulation` 过洞哨兵的 URDF 质量/转动惯量、接触摩擦、速度限制及全向轮 PID 力/力矩限制，按 `P=F·v+τ·ω` 计算机械功率。Gazebo 本身未提供电机电流/电压模型，因此不伪造电功率或效率。飞镖、场地增益、等级/经验与性能切换均已接入二维裁判验证流程。
