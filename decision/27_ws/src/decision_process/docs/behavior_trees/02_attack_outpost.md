# 02 打前哨子树 AttackOutpost

## 任务目标

比赛阶段开始后，哨兵优先前往地图点 `(16,11)`，指定敌方 6 号前哨站为自瞄目标并尝试射击。只有在收到完整裁判数据且确认敌方前哨站血量为 `0` 后，才释放后续行为。

## 输入与输出

| 类型 | 字段 | 用途 |
| --- | --- | --- |
| 输入 | `game_period` | 仅在比赛进行阶段 2 执行 |
| 输入 | `hp_sentry` | 哨兵存活时才执行 |
| 输入 | `hp_enemy[5]` | 敌方 6 号前哨站血量；`0` 表示任务完成 |
| 输入 | `color` | 己方颜色，用于反推出敌方装甲颜色 |
| 输入 | `ammo` | 有弹时才允许发送射击指令 |
| 输入 | 定位 `x、y` | 判断是否到达 `(16,11)` |
| 输入 | `target[6]` | 自瞄是否识别到 6 号前哨站 |
| 输入 | `target_distance[6]` | 必须为有限正数，才认为自瞄锁定有效 |
| 输出 | `posture=1` | 请求并应用进攻姿态 |
| 输出 | `/goal_pose=(16,11,1.0)` | 前往模拟击打点，参考坐标系为 `map` |
| 输出 | `target=6` | 指定敌方前哨站为自瞄目标 |
| 输出 | `color` | 己方红 `0` 时输出敌方蓝 `2`；己方蓝 `1` 时输出敌方红 `0` |
| 输出 | `tripod_mode` | 未看见前哨时为 `1` 转动搜索；有效锁定时为 `0` 停止转动 |
| 输出 | `shoot_mode` | 有效锁定且 `ammo>0` 时为 `1`，否则为 `0` |

## 子树完整流程

```text
MainTree (ReactiveFallback)
├── OutpostDestroyedRelease
│   ├── EnemyOutpostDestroyed
│   └── OtherBehaviorsPlaceholder
└── AttackOutpost
    ├── GameRunning
    ├── EnemyOutpostAlive
    ├── ApplyPosture(requested_posture=1)
    ├── NavigateToPose(16, 11, 1.0, map)
    └── EngageOutpost(target=6)
```

执行顺序不可交换：必须先完成导航，到点后才开始前哨搜索与射击。`ReactiveFallback` 每次 tick 都先检查前哨是否已经被摧毁，因此血量变为 `0` 后会立即中止攻击分支并进入后续行为占位分支。

## 到点后的单独决策

```text
前哨血量未知：不认为任务完成，不射击
前哨血量 > 0：继续本任务
前哨血量 == 0：清除射击和目标命令，释放后续行为

前哨不可见或距离无效：
    target = 6
    tripod_mode = 1
    shoot_mode = 0

前哨可见、距离有效、ammo > 0：
    target = 6
    tripod_mode = 0
    shoot_mode = 1

前哨可见、距离有效、ammo == 0：
    target = 6
    tripod_mode = 0
    shoot_mode = 0
```

“到点但看不见前哨”的处理采用转动云台继续搜索，而不是盲射。自瞄已经预先收到目标编号 6，一旦识别到前哨且距离数据有效，就停止转动并允许射击。

## 节点状态

| 节点 | SUCCESS | FAILURE | RUNNING |
| --- | --- | --- | --- |
| `EnemyOutpostDestroyed` | 完整敌方血量数组中 `hp_enemy[5]==0` | 未收到完整数据或血量大于 0 | 不使用 |
| `EnemyOutpostAlive` | 完整敌方血量数组中 `hp_enemy[5]>0` | 未收到完整数据或血量为 0 | 不使用 |
| `NavigateToPose` | 与 `(16,11)` 平面距离不大于容差 | XML 端口非法 | 未收到定位或尚未到达 |
| `EngageOutpost` | 前哨已被摧毁 | 目标编号不是 6，或队伍颜色非法 | 前哨存活，持续搜索或射击 |

敌方血量数组长度必须为 8。长度不正确时 `enemy_hp_valid=false`，即使补零后的 `hp_enemy[5]` 看起来为 0，也不能误判前哨已被摧毁。

## Groot2 文件

```text
behavior_trees/02_attack_outpost.xml
```

可在 Groot2 中调整击打点、到达容差、姿态冷却和目标编号。当前节点强制前哨目标编号必须为 6，防止误把该专用子树改成攻击其他单位。

## 测试覆盖

- 未收到裁判数据时不能把补零血量当成已摧毁。
- 敌方血量数组长度错误时不能完成任务。
- `hp_enemy[5]>0` 判定存活，`hp_enemy[5]==0` 判定摧毁。
- 红方正确指定蓝色目标，蓝方正确指定红色目标。
- 未识别目标、距离为 0 或距离为 NaN 时只搜索不射击。
- 识别前哨、有有效距离且有弹时停止云台并射击。
- 识别前哨但弹量为 0 时停止云台但不射击。
- 导航过程中持续发布 `(16,11,1.0,map)`。
- 前哨摧毁后清除 `shoot_mode` 和自瞄目标，允许后续行为。

ROS 联调模式：

```bash
ros2 run decision_process test_data_publisher \
  --ros-args -p simulate_attack_outpost:=true
```

该模式依次模拟：向 `(16,11)` 导航、到点但未看见前哨、识别并射击前哨、前哨血量归零。

## 合并约定

- 最终 23 个任务合并时，本任务放在开局任务优先级，完成黑板状态为“敌方前哨已摧毁”。
- `ApplyPosture` 仍由统一姿态管理逻辑执行，其他攻击节点不直接争抢姿态输出。
- `EngageOutpost` 只拥有自瞄目标、云台和射击命令；被更高优先级安全行为中止时会清除射击命令。
- 本独立子树严格等待前哨摧毁。最终总树中如需允许“无弹补给”或“阵亡复活”打断，应将这些生存行为放在打前哨之前，完成后再返回本任务。

## 当前边界

- `(16,11)` 是考核任务给出的模拟击打点，不是规则书中的官方前哨几何坐标。
- 任务没有给出固定射程，因此不额外设置最大射击距离，只要求距离数据为正且有效。
- `decide_yaw` 保持 `0.0`，真实瞄准角由自瞄模块处理。
- 当前完成条件只信任裁判系统血量，不通过视觉“看不见”推断前哨已摧毁。
