# 04 躲避行为子树 DodgeBehavior

## 任务目标

哨兵已经到达原导航目标并处于站定状态时，如果自瞄视野内没有任何敌方单位，但哨兵血量发生下降，则认为它可能正在遭受视野外攻击，立即通过短距离连续移动避免成为固定靶。最后一次受伤后经过可配置的安静时间，停止躲避并把控制权交还正常行为。

## 输入与输出

| 类型 | 字段 | 用途 |
| --- | --- | --- |
| 输入 | game_period | 仅在比赛进行阶段 2 执行 |
| 输入 | hp_sentry | 通过相邻裁判数据中的血量下降识别受伤事件 |
| 输入 | 自瞄 target[0..8] | 所有值均为 0 才认为视野内无敌方目标 |
| 输入 | 定位 x、y、yaw | 生成并判断短距离躲避目标 |
| 输入 | 导航 has_goal、reached | 只有原导航目标已经到达才允许触发 |
| 参数 | quiet_period_sec | 最后一次受伤后继续躲避的时间，默认 2 秒 |
| 参数 | step | 每次躲避目标的移动距离，默认 0.8m |
| 参数 | min/max x/y | 限制躲避目标不越出允许地图区域 |
| 输出 | posture=3 | 躲避使用移动姿态 |
| 输出 | shoot_mode=0 | 没有可见目标时停止射击 |
| 输出 | tripod_mode=1 | 躲避时继续旋转云台搜索 |
| 输出 | target=0 | 清除之前遗留的自瞄目标 |
| 输出 | /goal_pose | 连续发布地图范围内的短距离躲避目标 |

## 受伤检测

ReceiveData.msg 没有“正在受到伤害”标志，因此通过血量变化检测：

    第一次收到 hp_sentry：只建立基线，不认为受伤
    current_hp < previous_hp：记录 last_damage_time
    current_hp == previous_hp：不更新受伤时间
    current_hp > previous_hp：认为是回血，不更新受伤时间

    recent_damage = now - last_damage_time <= quiet_period_sec

如果连续受到多次伤害，每次血量下降都会刷新 last_damage_time，因此躲避持续到最后一次受伤后的安静时间结束。

## 触发条件

以下条件必须同时成立：

1. 已收到裁判数据，比赛处于阶段 2，哨兵存活。
2. 已收到自瞄数据，target[0..8] 全部为 0。
3. hp_sentry 最近发生过下降，且仍在安静时间窗口内。
4. 正常行为曾设置导航目标，并且该目标已经到达。

自瞄数据尚未收到时不会使用“没有目标”这一假设触发躲避。哨兵仍在正常移动途中时也不会触发，严格符合“目前已到达目标点、处于站定状态”的要求。

## 子树完整流程

    MainTree (ReactiveFallback)
    ├── DodgeBehavior
    │   ├── GameRunning
    │   ├── NoEnemyVisible
    │   ├── RecentDamage(quiet_period_sec=2.0)
    │   ├── NavigationGoalReached
    │   ├── SetCombatIdle
    │   ├── ApplyPosture(requested_posture=3)
    │   └── EvadeUntilSafe
    └── NormalBehaviorDemo: NavigateToPose(5,5)

独立 XML 中的 (5,5) 只用于模拟一个普通行为目标：先到点站定，之后才能测试受伤躲避。最终合并时，该演示分支会替换为其他真实任务。

DodgeSequence 使用有记忆的 Sequence，不是 ReactiveSequence。原因是躲避动作发布新目标后，原来的 NavigationGoalReached 自然会变为假；如果每一帧重新检查该触发条件，会立即中止刚启动的躲避。动作启动后由 EvadeUntilSafe 自己持续检查受伤窗口、敌人可见性和比赛状态。

## 躲避轨迹

默认方向依次为：

    当前位置 + (0, +step)
    当前位置 + (+step, 0)
    当前位置 + (0, -step)
    当前位置 + (-step, 0)
    循环

每到达一个躲避点，就按照下一个方向生成新目标。目标会限制在：

    x ∈ [0.2, 27.8]
    y ∈ [0.2, 14.8]

任务给出的场地为 28m × 15m，默认预留 0.2m 边缘，避免目标落在地图边界上。若某个方向经过裁剪后与当前位置重合，会尝试后续方向；四个方向都无法产生有效位移时才停止躲避并报告失败。

## 恢复正常行为

EvadeUntilSafe 在以下任一情况发生时停止发布躲避目标，并立即让主回退节点执行正常行为：

- 距最后一次受伤超过 quiet_period_sec。
- 自瞄重新识别到任意目标。
- 比赛离开阶段 2。
- 哨兵血量变为 0。

躲避结束后不强行返回触发前的坐标。正常行为会重新发布自己的目标，因此由原行为决定返回、巡逻、攻击或执行其他任务。

## 节点状态

| 节点 | SUCCESS | FAILURE | RUNNING |
| --- | --- | --- | --- |
| NoEnemyVisible | 已收到自瞄数据且全部目标不可见 | 未收到自瞄数据或存在可见目标 | 不使用 |
| RecentDamage | 仍在最后一次受伤后的时间窗口 | 未受伤、窗口结束或参数非法 | 不使用 |
| NavigationGoalReached | 存在正常导航目标且已到达 | 未设置目标、仍在移动或目标被中止 | 不使用 |
| EvadeUntilSafe | 不使用 | 受伤解除、发现敌人、比赛结束、阵亡或参数无效 | 持续生成躲避目标 |

## 测试覆盖

- 第一帧血量只建立基线，不误判受伤。
- 血量下降立即触发受伤窗口，超过安静时间后失效。
- 回血不会被误判为新的伤害。
- 连续受伤会延长躲避时间。
- 未收到自瞄数据时不能判断“视野内无敌人”。
- 自瞄数组任意目标可见时都不能触发。
- 正常点位可以生成 0.8m 躲避目标。
- 靠近边界时目标会被限制在地图范围内。
- 非法步长或地图范围会被拒绝。
- ROS 联调覆盖正常到点、血量下降、连续躲避点和安静期结束后回归正常目标。

ROS 联调模式：

    ros2 run decision_process test_data_publisher +      --ros-args -p simulate_dodge:=true

## 合并约定

- 最终总树中，躲避任务应高于普通站桩、巡逻和常规攻击导航，避免站定时继续成为固定靶。
- 阵亡复活、比赛结束归位、无弹补给和低血回血等全局任务的最终优先级，在总树合并阶段统一处理。
- 躲避只在触发瞬间要求“原导航目标已到达”；进入动作后由动作内部管理连续目标。
- 正常行为在躲避结束后必须重新发布自己的导航目标，不能依赖躲避前被覆盖的旧命令。

## 当前边界

- 仅能通过血量下降推断受伤，无法区分弹丸伤害、撞击、判罚扣血或其他扣血来源。
- 默认 2 秒安静时间和 0.8m 步长是工程参数，不是规则书硬编码值。
- 当前使用四方向折线移动，没有接入局部代价地图；真实导航模块仍负责避障和路径可行性。
- 如果定位漂移导致系统错误认为原目标已到达，可能误触发躲避，需要导航状态接口进一步提供明确到达结果。
