# RMUC 2026 Pygame 二维验证器

这是一个与 ROS 2/Gazebo 解耦的轻量二维验证程序，用于先行确认哨兵坐标、任务场景输入、人工移动、小陀螺、云台和高层决策输出。

## 坐标和地图

- 场地世界坐标为 `28 m x 15 m`，原点位于左下角，`x` 向右、`y` 向上。
- 哨兵初始坐标为 `(4.971, 7.5)`。
- 左下角补给区为 `x = 0.5~3.7 m、y = 0.2~2.4 m`，区域内任意位置均可回血、领取弹药和解除复活后的射击锁；导航参考点为 `(2, 1)`。
- 前哨攻击点为 `(17, 10)`，与前哨站实际距离小于 4 米。
- 地图来自仓库 `定位导航参考资料/26_task_ws/src/compre_task/map/rmuc2026.pgm`。
- 源地图参数采用配套 YAML：分辨率 `0.05 m/px`、原点 `(-0.55, 0)`。程序将源图精确裁成世界坐标 `[0, 28] x [0, 15]`，没有拉伸坐标范围。

## 运行

Windows PowerShell：

```powershell
cd "decision/27_ws/pygame_sim"
python -m venv ".venv"
& ".venv/Scripts/python.exe" -m pip install -r "requirements.txt"
& ".venv/Scripts/python.exe" "main.py"
```

Linux：

```bash
cd "decision/27_ws/pygame_sim"
python3 -m venv ".venv"
".venv/bin/python" -m pip install -r "requirements.txt"
".venv/bin/python" "main.py"
```

Linux 下接入真实 ROS 2/BehaviorTree.CPP 的一键启动方式：

```bash
./run_behavior_tree_sim.sh
```

脚本会构建 `decision_process`，启动 C++ 行为树与 ROS/UDP 桥接，再启动
Pygame。左侧“决策来源”显示“ROS 行为树在线”时表示真实行为树已经接管；
连接失败时会自动显示“Python 本地回退”。集成模式需要 ROS 2 Jazzy
和 `behaviortree_cpp` 4.x。

## 控制

| 输入 | 行为 |
| --- | --- |
| `1/2/3/4/8`（主键盘或小键盘） | 选择对应编号的蓝方地面机器人 |
| `9`（主键盘或小键盘） | 选择己方哨兵机器人 |
| `W/A/S/D` 或方向键 | 沿世界坐标轴移动；对角输入会归一化 |
| `空格` | 暂停或继续比赛；暂停时冻结计时、自动移动、射击耗弹和扣血，但仍可人工调整机器人位置 |
| `鼠标左键` | 选择己方哨兵后按住人工开火；只有枪口实际对准射程内目标才扣血，点击界面按钮不会开火 |
| `P` | 暂停或继续比赛的备用按键 |
| `0` 或左/右 `Shift` | 退出人工控制并切回行为树/本地自动控制 |
| `R` | 重新启动当前验证场景，切回自动控制并复位行为树运行状态 |
| `Ctrl+S` | 保存当前场景，包括全部位置、血量、弹量、时间、角度和巡逻模式 |
| `Esc` | 退出程序 |

被选中的蓝方机器人会显示金色控制环，顶部坐标栏切换到该机器人；每个敌方机器人上方会显示编号和名称。蓝方 5 号为空中单位，本二维地面移动验证不提供 `5` 号人工控制。云台在没有射击锁定时自动扫描，发现行为树选定目标后由模拟自瞄逐步对准。地图使用与云台同轴转动的两个扇形：青色 6.2 米扇形表示可发现并上报行为树的目标，橙色 4.0 米扇形表示允许开火扣血的攻击范围。行为树的 `shoot_mode` 只代表开火请求，地图还会验证攻击范围和 4° 枪口夹角；未对准或只进入探测区时不会扣血。按 `9` 进入己方哨兵人工控制后，可在枪口扫过目标时按住鼠标左键锁住当前枪口方向并人工射击，松开左键后继续扫描。任意一方基地血量归零时，比赛立即结束并触发归位。

自瞄只向行为树发送相机视野内目标的相对极径和极角。ROS 桥同时发布机器人自身的 `map -> camera_link` 变换，决策端据此解算目标地图坐标并生成追击点；可见目标不会读取裁判/雷达中的敌方绝对坐标。雷达绝对坐标仅保留给“自瞄无目标”时的独立雷达联动逻辑。

## 场景注入

场景键只修改裁判系统或感知输入，不会替代移动控制。导航目标以黄色菱形显示，机器人仍需使用 `9` 和 `W/A/S/D` 或方向键移动，用来检查目标点、到达条件和行为切换。

| 输入 | 注入条件 |
| --- | --- |
| `F1` | 重置比赛、哨兵和所有场景状态 |
| `F2` | 己方前哨站被摧毁，验证小陀螺开启 |
| `F3` | 注入一次视野外伤害，哨兵扣除 50 HP |
| `F4` | 弹量清零并增加 100 发待领取弹药 |
| `F5` | 敌方前哨站被摧毁，解除开局任务优先级 |
| `F6` | 将哨兵设为 150 HP，验证防御增益特化回血阈值 |
| `F7` | 结束比赛，验证返回 `(4.971, 7.5)` |
| `F8` | 哨兵阵亡，5 秒后确认复活并要求返回补给区解锁射击 |
| `F9` | 跨过巡逻资源边界进行验证：HP < 150 或经济 < 400 时保守，否则激进 |
| `F10` | 完整重置比赛：时间、位置、血量、弹药、经济、建筑、控制状态和行为树状态全部复位 |

场地还会显示两方基地/前哨、数据集中的 6 个蓝方单位、补给区域、两套巡逻路线、6.2 米探测扇形、4.0 米攻击扇形、当前行为、血量、弹量、经济以及姿态/复活/云台/小陀螺/射击/目标输出。保守路线与激进路线会同时显示，当前使用的路线以更粗、更亮的线条高亮；当 HP < 150 或经济 < 400 时选择保守路线并关闭云台，否则选择激进路线并开启云台。经济位于左侧底部，可按 50 为步长在 0–1000 范围内调节。两套路线均按 `1 → 2 → 3 → 1` 闭环巡逻。射速和单发伤害也可在左侧调节：依据规则手册中 17mm 弹丸 50ms 最小检测间隔，射速范围设为 1–20 发/秒；机器人与前哨站装甲的 17mm 原始单发伤害范围设为 1–20 HP，默认均取规则值 20。

界面采用左右属性栏和中央地图布局：己方、裁判系统与任务状态位于左侧，敌方血量和执行输出位于右侧；血量、弹量、防御增益、基地和前哨使用进度条显示。左侧提供“自动控制”和“重新启动”按钮，与 `0`、`R` 快捷键作用相同。比赛时间旁的 `-`、`+` 每次调整 10 秒；“重置”会将时间、全部单位位置、属性、建筑、人工控制和行为树运行状态恢复为新比赛默认值，但不会删除底部长期场景存档。己方哨兵血量、弹量、防御增益、前哨、基地和所有敌方单位都可通过旁边的 `-`、`+` 调整。界面可见文字统一使用中文。

窗口底部是类似 Excel 工作表的场景存档栏。按 `Ctrl+S` 或点击 `+` 会新建“场景 1、场景 2……”标签，存档持久化在项目内的 `scenario_saves.json`；程序下次启动时会自动读取，因此关闭窗口或重启电脑后仍然存在。点击任一标签会恢复当时的全场状态，点击标签右侧的 `×` 会立即删除该存档并同步更新本地文件。载入场景后点击“重新启动”或按 `R`，程序会发送新比赛复位信号并切回自动控制，让行为树从该存档状态重新开始验证。

场景遵守主行为树优先级。开局会在前往前哨攻击点时开启云台扫描；2 号工程机器人不会加入攻击目标。只要在 6.2 米探测范围内发现低于 50 HP 的敌方机器人，该目标会立即抢占前哨和回血任务：4 米外主动追击，进入 4 米后攻击，即使此时前哨已经可以射击或己方哨兵已经低于回血阈值。残血目标消失或被摧毁后，再恢复前哨任务或回血。1 秒内累计扣血达到 30 且达到阈值时未检测到敌人，会立即切换为防御姿态、高速小陀螺、开启云台并执行不规则局部机动；一次 25 HP 误伤不会触发，两次快速点击累计 50 HP 会触发。连续 5 秒无显著伤害后继续原任务。

任务说明的生产代码覆盖情况见 [`TASK_COVERAGE.md`](TASK_COVERAGE.md)。Pygame 中的场景显示用于验证输入和期望结果，不代表对应能力已经进入 ROS 2 主行为树。
