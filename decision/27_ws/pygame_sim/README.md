# RMUC 2026 Pygame 二维验证器

这是一个与 ROS 2/Gazebo 解耦的轻量二维验证程序，用于先行确认哨兵坐标、任务场景输入、人工移动、小陀螺、云台和高层决策输出。

## 坐标和地图

- 场地世界坐标为 `28 m x 15 m`，原点位于左下角，`x` 向右、`y` 向上。
- 哨兵初始坐标为 `(4.971, 7.5)`。
- 左下角补给区为 `x = 0.5~3.7 m、y = 0.2~2.4 m`，区域内任意位置均可回血、领取弹药和解除复活后的射击锁；导航参考点为 `(2, 1)`。
- 前哨攻击点为 `(16, 11)`。
- 地图来自仓库 `定位导航参考资料/26_task_ws/src/compre_task/map/rmuc2026.pgm`。
- 源地图参数采用配套 YAML：分辨率 `0.05 m/px`、原点 `(-0.55, 0)`。程序将源图精确裁成世界坐标 `[0, 28] x [0, 15]`，没有拉伸坐标范围。

## 运行

Windows PowerShell：

```powershell
cd "decision/27_ws/pygame_sim"
python -m venv ".venv"
& ".venv/Scripts/python.exe" -m pip install -r "requirements.txt"
& ".venv/Scripts/python.exe" "main.py"
```

Linux：

```bash
cd "decision/27_ws/pygame_sim"
python3 -m venv ".venv"
".venv/bin/python" -m pip install -r "requirements.txt"
".venv/bin/python" "main.py"
```

## 控制

| 输入 | 行为 |
| --- | --- |
| `1/2/3/4/8`（主键盘或小键盘） | 选择对应编号的蓝方地面机器人 |
| `9`（主键盘或小键盘） | 选择己方哨兵机器人 |
| `W/A/S/D` | 沿世界坐标轴移动；对角输入会归一化 |
| 左或右 `Shift` | 释放当前机器人，立即停止响应移动键 |
| `Esc` | 退出程序 |

被选中的蓝方机器人会显示金色控制环，顶部坐标栏切换到该机器人。蓝方 5 号为空中单位，本二维地面移动验证不提供 `5` 号人工控制。小陀螺只在己方前哨站被摧毁后自动旋转。云台在没有射击锁定时自动扫描，射击已选目标时停止旋转。人工移动控制不会改变这两个决策输出。

## 场景注入

场景键只修改裁判系统或感知输入，不会替代移动控制。导航目标以黄色菱形显示，机器人仍需使用 `9` 和 `W/A/S/D` 移动，用来检查目标点、到达条件和行为切换。

| 输入 | 注入条件 |
| --- | --- |
| `F1` | 重置比赛、哨兵和所有场景状态 |
| `F2` | 己方前哨站被摧毁，验证小陀螺开启 |
| `F3` | 注入一次视野外伤害，哨兵扣除 50 HP |
| `F4` | 弹量清零并增加 100 发待领取弹药 |
| `F5` | 敌方前哨站被摧毁，解除开局任务优先级 |
| `F6` | 将哨兵设为 150 HP，验证防御增益特化回血阈值 |
| `F7` | 结束比赛，验证返回 `(4.971, 7.5)` |
| `F8` | 哨兵阵亡，5 秒后确认复活并要求返回补给区解锁射击 |
| `F9` | 在保守巡逻与激进巡逻之间切换，地图路线和导航目标同步更新 |
| `F10` | 仅将比赛时间重置为 420 秒，不重置机器人和任务状态 |

场地还会显示两方基地/前哨、数据集中的 6 个蓝方单位、补给区域、当前巡逻路线、5 米云台视野、当前行为、血量、弹量以及姿态/复活/云台/小陀螺/射击/目标输出。保守路线靠近己方半场，激进路线向中部和敌方半场展开；两套路线均按 `1 → 2 → 3 → 1` 闭环巡逻。

界面采用左右属性栏和中央地图布局：己方、裁判系统与任务状态位于左侧，敌方血量和执行输出位于右侧；血量、弹量、防御增益、基地和前哨使用进度条显示，地图下方不再放置状态文字。点击比赛时间旁的“重置”可以恢复 420 秒；点击己方哨兵或任一敌方单位血量旁的 `-`、`+` 可以扣除或恢复对应血量。界面可见文字统一使用中文。

场景遵守主行为树优先级。开局打前哨优先于无弹、躲避和巡逻，因此要单独观察这些低优先级行为时，先按 `F5` 将敌方前哨设为已摧毁，再注入对应条件。躲避还要求哨兵已经到达当前巡逻目标：先人工移动到黄色导航菱形，再按 `F3`。

任务说明的生产代码覆盖情况见 [`TASK_COVERAGE.md`](TASK_COVERAGE.md)。Pygame 中的场景显示用于验证输入和期望结果，不代表对应能力已经进入 ROS 2 主行为树。
